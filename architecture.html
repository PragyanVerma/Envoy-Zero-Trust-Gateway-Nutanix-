Zero-Trust Intelligent Gateway

A production-grade, ML-powered edge gateway built with Envoy Proxy

Overview

This project demonstrates an intelligent API gateway that sits in front of backend services. Every request passes through it. The gateway verifies identity (JWT), runs an AI model to calculate a trust score, and dynamically routes users to either a standard backend or a restricted sandbox — all in under 5 milliseconds.

Problem Statement Keywords Addressed

Zero-Trust → JWT + per-request verification  |  Intelligent → ML Trust Scoring  |  Security → Rate Limiting + Sandboxing  |  Scale → Redis Distributed Memory  |  Performance → Circuit Breakers + Retries  |  Deep Observability → Prometheus, Grafana, Jaeger

Request Flow

Here is exactly what happens when a user sends a request to the gateway:

1
User sends HTTP request with JWT token
curl -H "Authorization: Bearer eyJhbG..." http://localhost:10000/
2
Envoy validates the JWT signature (RSA-256)
If invalid or missing → 401 Unauthorized. Backend never touched.
3
Envoy asks the ML Auth Service: "Trust this user?"
Forwards JWT claims (caller identity) via x-forwarded-jwt-claims header
4
Auth Service queries Redis for the caller's request rate
Sliding window: counts requests in the last 10 seconds using Redis Sorted Sets
5
ML Model calculates Trust Score (0.0 → 1.0)
Features: request_rate, is_sensitive_endpoint, hour_of_day → Logistic Regression
Score ≥ 0.5 → STANDARD
Trusted user → real backend
Score < 0.5 → SANDBOX
Suspicious user → isolated environment

Architecture — All 8 Containers

🛡️
Envoy Proxy Zero-Trust
Port 10000 (Gateway)  |  Port 9901 (Admin)

The front door to the entire system. Every request must pass through Envoy. No service is accessible directly.

  • JWT Authentication: Validates RSA-256 signed tokens at the edge. Invalid tokens are rejected immediately (401) without ever reaching the backend.
  • External Authorization: Calls the ML Auth Service to get a trust decision for every request.
  • Dynamic Routing: Routes trusted users (score ≥ 0.5) to the Standard backend and suspicious users (score < 0.5) to the Sandbox. Uses clear_route_cache: true to enable re-routing after the auth filter runs.
  • Retry Policy: If a backend returns a 5xx error, Envoy silently retries up to 2 more times. The user never sees the failure.
  • Circuit Breaker: Limits max connections (100), pending requests (50), and retries (3) per cluster. Prevents cascading failures.
  • Outlier Detection: If a backend returns 3 consecutive 5xx errors, Envoy ejects it from the pool for 30 seconds.
  • Distributed Tracing: Generates OpenTelemetry trace spans for every request and sends them to Jaeger via gRPC.
🧠
ML Auth Service (FastAPI) Intelligent
Port 8000

The brain of the system. A Python FastAPI app that runs an ML model to make trust decisions in real-time.

  • Step 1: Reads the caller's identity from JWT claims (the sub field becomes the caller_id).
  • Step 2: Queries Redis for the caller's request count in the last 10 seconds.
  • Step 3: Extracts 3 features: request_rate, is_sensitive_endpoint (path contains "admin", "delete", "refund"), hour_of_day.
  • Step 4: Runs inference using a pre-trained Scikit-Learn Logistic Regression model (trust_model.pkl). Returns a probability between 0.0 and 1.0.
  • Step 5: Sets the routing header (x-route-to: standard or sandbox) and the x-trust-score header.
  • Step 6: Logs the decision to /app/logs/requests.log as JSON lines for the Streamlit dashboard.
⚡
Redis Scale
Port 6379

Ultra-fast shared memory for distributed rate limiting. Uses Sorted Sets to implement a sliding window algorithm.

  • ZREMRANGEBYSCORE — delete timestamps older than 10s
  • ZADD — record current timestamp
  • ZCARD — count remaining = request_rate
  • EXPIRE — auto-cleanup inactive users

All 4 commands execute atomically via a Redis Pipeline (single round-trip).

🔍
Jaeger Observability
Port 16686

Distributed tracing system. Visualizes the journey of every single request as a waterfall timeline.

  • Shows exact time spent in Envoy, Auth Service, and Backend
  • Pinpoints which component caused latency
  • Receives traces via OpenTelemetry (OTLP gRPC on port 4317)
✅
Standard Backend
Port 5001

Simple Flask app for trusted users (trust score ≥ 0.5). Returns:

{"message": "Hello from the STANDARD backend"}

🔒
Sandbox Backend
Port 5002

Isolated Flask app for suspicious users (trust score < 0.5). Returns:

{"message": "Rate limited - routed to SANDBOX"}

📊
Prometheus Observability
Port 9090

Time-series metrics database. Scrapes Envoy's /stats/prometheus endpoint every 5 seconds. Stores request counts, latencies, error rates, and circuit breaker status.

📈
Grafana Observability
Port 3000

Professional visualization dashboard. Auto-provisioned with 6 panels: Traffic per cluster, ML latency, Circuit breaker status, Retries & errors, Outlier ejections, Success rate gauge.

The ML Model

A Scikit-Learn Logistic Regression model trained offline on 300 rows of synthetic data. Saved as trust_model.pkl and loaded into the Auth Service at container startup. Only inference happens during live traffic (not training).
